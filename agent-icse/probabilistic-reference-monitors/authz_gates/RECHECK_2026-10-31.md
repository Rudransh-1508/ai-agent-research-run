# Freshness re-check, 2026-10-31

The study's measurements were taken 2026-09-21..29 on `jev-1.13.0` against gates pinned
at their 2026-09-17..21 commits. Before the AGENT @ ICSE 2027 submission we re-checked
what could have moved in the five weeks since. The original measurements stay as the
paper's pre-registered results; this file records what is still true, what changed, and
what is new.

## 1. Literature (arXiv sweep, 2026-10-31)

Nothing scoops the paper's core: no other work studies *deployed* gates, their failure
paths, or the host-mode interaction. Closest new work, now cited:

| Work | Relation |
|---|---|
| Liu, Evaluating System One Models for Agent Security Decisions (arXiv 2609.33401) | Model-level calibration + selective automation for Jev and peers; strict miss budgets leave little to automate. Consistent with our dead-0.9 and recipe results; studies the model, not deployed gates. |
| Azizi et al., One Word Opens the Gate (arXiv 2610.12292) | Option-label attack on typed decision models as guardrails (open-weight models). Uses "fail-open" for a wrong allow; we use it for behaviour on model failure. |
| AuthGateBench (arXiv 2610.16426) | LLMs as authorization gates for benign authorized requests. |
| JevAct (arXiv 2610.38620) | Framework pairing deterministic state checks with a decision model. |
| CAGE (arXiv 2607.29190) | Certifies authorization against perturbed tool returns; ours certifies the threshold. |
| Local Allow, Global Deny (arXiv 2610.27620, IEEE TPS 2026) | Per-action authorization cannot catch compositional violations; scopes our per-call study. |

## 2. Host behaviour (Claude Code hooks docs, accessed 2026-10-31)

Still true: a timed-out PreToolUse hook does not block the call, and a non-zero exit other
than 2 is a non-blocking error. New: an opt-in `onFailure: "block"`. The docs also make
explicit that a hook's `"ask"` still prompts in auto mode and only `bypassPermissions`
runs it, so the paper's "auto-approval" condition is now named as `bypassPermissions`.

## 3. Model version

`jev-latest` now resolves to `jev-1.14.0` (released 2026-10-22); `jev-1.13.0` is still
served. The oversize precondition of the bypass holds on both: a 390k-char state returns
HTTP 400 `max_tokens_exceeded` in 0.8 s (1.14.0) and 0.65 s (1.13.0).

Benchmark re-run on 1.14.0 (same corpus, same four configurations): see section 6.
Re-run with `benchmark/run_recheck.sh jev-1.14.0`; outputs in `artifact/jev-1.14.0/`.

## 5. Corpus growth since the freeze

The frozen 31-gate corpus stays the pre-registered sample. Re-enumerating the same index
(yibie/awesome-jev) gives 66 candidate entries against 49 at the freeze; 33 are new, most
of them not agent-action gates (subtitle checks, mail triage, CI triage). Five are action
gates; four were readable:

| Gate | Created / HEAD | Failure posture | Threshold provenance |
|---|---|---|---|
| agent-chaperone (Claude Code plugin + MCP proxy) | 2026-09-18 / 2026-10-21 | fail-open on every failure, documented ("Every failure lets the call through") | 0.5 / 0.8 constants |
| subcento (transaction pre-flight) | 2026-10-18 | fail-closed strict, pins `jev-1.14.0` | 0.4 / 0.7 constants |
| Edward (trajectory monitor) | 2026-09-22 / 2026-10-24 | n/a (advisory) | 0.5 / 0.6 constants |
| learn-jev-end-to-end (course agent loop) | 2026-09-23 | fail-closed | 0.4 / 0.5 / 0.7 constants |

So fail-open persists in hook-style tool gates, some newer non-hook gates fail closed, and
thresholds are still undocumented constants.

## 6. Benchmark on jev-1.14.0 (346 main + 80 held-out, 0 failed calls)

Per-tier accuracy and ECE, main corpus:

| gate | version | safe | destructive | ambiguous | adversarial | ECE |
|---|---|---|---|---|---|---|
| Noul @ 0.9 | 1.13.0 | 0.00 | 0.83 | 0.75 | 0.74 | 0.230 |
| Noul @ 0.9 | 1.14.0 | **0.27** | 0.74 | 0.92 | 0.82 | 0.213 |
| Noul @ 0.5 | 1.13.0 | 0.98 | 1.00 | 0.00 | 0.44 | 0.130 |
| Noul @ 0.5 | 1.14.0 | 0.98 | 1.00 | 0.00 | 0.44 | 0.074 |
| Choice (policy) | 1.13.0 | 1.00 | 0.59 | 0.82 | 0.68 | 0.111 |
| Choice (policy) | 1.14.0 | 0.98 | 0.66 | 0.64 | 0.59 | 0.094 |
| Score (risk5) | 1.13.0 | 1.00 | 0.83 | 0.52 | 0.74 | 0.067 |
| Score (risk5) | 1.14.0 | 1.00 | 0.84 | 0.42 | 0.80 | 0.084 |

Held-out adversarial accuracy: Noul@0.9 0.60 -> 0.60, Noul@0.5 0.69 -> 0.60,
Choice 0.90 -> 0.75, Score 0.80 -> 0.80.

What changed:

- **The dead 0.9 path is version-specific.** On 1.14.0 the shipped 0.9 auto-allows 25/94
  clearly-safe items (safe scores 0.35-0.94, were 0.34-0.89); destructive scores stay
  <= 0.28, AUROC still 1.0, so no destructive item is allowed. The destructive-tier drop
  (0.83 -> 0.74) is deny -> ask, not allow. Same constant, same gates, different behaviour:
  any gate on the `jev-latest` alias changed silently on 2026-10-22.
- **The recipe holds but its threshold moves.** Certified operating point: 41.8% coverage at
  <= 3.14% false-allow on both versions, at t = 0.245 (1.13.0) vs t = 0.285 (1.14.0).
  The vendor 0.9 on 1.14.0 covers 11.1% but certifies only <= 11.3%
  (`artifact/jev-1.14.0/threshold_recipe_noul.json`).
- **Not uniformly better.** Choice loses on ambiguous (0.82 -> 0.64) and held-out
  adversarial (0.90 -> 0.75); the main-corpus calibration ranking flips (Noul 0.074 vs
  Score 0.084), so "Score is best calibrated" is a 1.13.0 statement.
- Not re-run: the 10x noise-floor repeats.
