# Corpus notes — surprises, exclusions, threats to validity

Date: 2026-09-21. Companion to CORPUS_TABLE.md (generated by build_table.py).

## Surprises

1. **The pilot sweep's headline miscounted.** The prior sweep reported "11 of 16 documented
   error paths fail open." Reading every pilot repo at the pinned SHA, the verified count is
   **10/16** failing open on at least one failure mode: jev-git is fail-closed
   (src/main.rs:153-155, 203-211, 227-236 — every failure exits 2, "Missing answer = fail
   closed"), is-malicious is fail-closed (unscanned chunks exit 2, README.md:39), and Reflex
   is partial (the deterministic fallback still gates protected paths and dangerous patterns,
   gate.ts:294-307). The direction of the finding survives; the exact number did not.

2. **P1 sits near its boundary and the split disagrees.** Full corpus: 16/31 = 52% fail open
   on at least one mode (supported, barely). Pilot: 10/16 = 62%. Held-out: 6/15 = 40% (not
   supported). The fail-open majority is a property of the hook-style gates that dominate the
   pilot set; the held-out set contains more CI-style tools (Hunch, jev-pref, taste-lint,
   is-malicious-style exit-code gates) that fail closed because any non-zero exit fails the
   pipeline. Where the boundary sits depends on the partial gates (Reflex, jev-commit,
   Foreman, Sniff Test, jev-harness), each documented per-row in the table.

3. **jev-harness silently decides on simulated answers.** On a connection failure or timeout
   its client substitutes a regex-based *simulated* Jev response and the gate decides on that
   (packages/rust/src/client.rs:189-192, "fall back gracefully to simulation"). The result
   carries an `is_mock` flag, but the gate acts either way. No other gate in the corpus
   fabricates model answers on failure; most pick allow or deny. (HTTP error statuses do exit
   2; missing answers default to non-blocking values — hence partial.)

4. **Fail-open is usually a deliberate, documented design choice, not an oversight.**
   jev-guard: "default is fail-open: a dead API must not freeze the agent" (hook.js:140).
   limpet: "No key, API down, timeout, or any other error => exit 0 silently" (limpet.py:18).
   jev-belay: "Every error path exits 0" (belay.mjs:6). jev-use: "a judgment sidecar being
   down must never block the agent" (cli.ts:154-155). Abide encodes it as a project rule
   ("Every hook path exits 0", .abide/rubric.json). The corpus is a natural experiment in
   stated availability-over-safety posture.

5. **The vendor docs' illustrative thresholds propagate.** docs.typesafe.ai illustrates
   `noul > 0.9` (primitives/noul) and a 0.5 confidence floor / `confidence > 0.9` high-stakes
   band (confidence) — accessed 2026-09-21. 8 of 31 gates ship a 0.9 or 0.5 constant; exactly
   one (jev-engineering, DENY_ABOVE 0.90) pairs it with a README that says thresholds should
   come from your own logs while shipping the vendor's round number as the default.

6. **One gate never calls the model at all.** jev-superpowers advertises "completion gates"
   powered by Jev, but no file in the repo references the API; its hooks are deterministic
   bash or delegate to jev-git/limpet/supercov. It is also one of several same-author,
   same-week repos (AkashPriyadarshii: jev-git, jev-scout, jev-seo, jev-curate,
   jev-superpowers) — the curator's bulk-submission warning made concrete. (jev-git itself is
   real, minimal, fail-closed code and stays in the corpus.)

7. **jev-harness was nearly mis-excluded.** Its awesome-jev entry reads like launch prose
   ("triaging test tracebacks in < 2ms"), and the lit review flagged it as scaffold-shaped.
   The checkout contains real Rust/Python/TS gate code with three working gates. Initial
   exclusion was reversed after cloning — recorded here because it changed the corpus size.

8. **The strongest engineering is in the smallest repos.** hermes-jev-approvals admits its
   thresholds are "round numbers" and documents why each question exists against measured
   failures; jev-belay swept its one threshold on 100 labeled stops and reports the interval;
   pi-verdict fails closed on contract drift *by construction* (missing confidence = malformed
   = deny). Meanwhile the largest "framework" entries are the thinnest gates.

## Exclusions (beyond the automated filters in gates.json)

- **stanley-code** — read in full; explicitly advisory ("advisory only", "this is not an
  approval", exit codes 1/2 deliberately unused, src/cli/output.ts:15,36,48). Fails
  criterion (a): it decides nothing about whether an action proceeds.
- **jev-superpowers** — fails criteria (a)/(b): no Jev call anywhere in the repo (see above).
- **Blink, Yappy, Jev AI, Elvex blog** — no public source URL; criterion (b) unverifiable.
- **harshwasan/jev-sentinel** — does not exist (confirmed by the prior audit and re-checked
  against the current list; never present in awesome-jev's current categories).
- **Keyword-matched non-gates** (full list with reasons in gates.json): routers, SDKs, MCP
  adapters that expose Jev as a tool without gating anything themselves, context-compaction
  plugins, browser/game loops, and Discord/Telegram/YouTube/Twitch moderators (not
  agent-action gates). JarvisCore is a framework whose only gate-like behavior is a RAG
  injection filter; excluded as not an action-authorization gate.
- **Borderline but included:** mastra-jev-moderation (gates user input to an assistant, not
  tool calls — included as a decision gate from Content Moderation); jev-review and OpenWork
  (review/verification gates whose "block" is a report outcome or an un-produced plan, not a
  hook exit code); r2r-jev (a governance demo binary, not an installed hook); wakegate (gates
  waking, where fail-open is the safe direction). Each is flagged in its table row.

## Threats to validity

- **Convenience sample.** The corpus is one curated list (yibie/awesome-jev) plus
  decision-gate entries reachable from it. Gates not listed there (e.g. inside closed
  products) are invisible. Criterion (d) makes this explicit.
- **Same-day bulk submissions.** The curator warns that same-day multi-repo authors can
  satisfy inclusion rules while shipping scaffolds. jev-superpowers is exactly that shape and
  was excluded on read; other same-author repos (jev-git) are real but thin. Corpus
  composition may over-represent launch-window enthusiasm over durable deployments.
- **Pilot/held-out asymmetry.** The pilot set was selected by a prior sweep before
  pre-registration; it over-represents hook-style fail-open gates. All split results are
  reported alongside the full corpus for this reason.
- **Classification judgment calls.** "Partial" gates and the borderline inclusions above are
  judgment calls; every one carries a file:line quote so a reviewer can re-adjudicate.
- **Point-in-time.** SHAs are pinned (2026-09-21), but the list and the vendor docs move;
  the vendor-threshold evidence (P3) cites docs.typesafe.ai pages as accessed 2026-09-21.
- **Static read, not execution.** Error-path classifications come from reading code, not from
  fault injection. Where a hook's host changes semantics (e.g. Claude Code's treatment of
  hook exit codes), the host's documented behavior is assumed.
