# Jev / TypeSafe AI — Primary-Source Research Findings

**Date compiled:** 2026-09-21
**Scope:** Factual picture of TypeSafe AI's "System One Models" and their first model "Jev", from primary sources (company site, docs, evals site, GitHub) plus independent coverage (Hacker News, practitioner blogs, third-party reimplementations).

---

## 1. What Jev is (verified facts)

These are facts confirmed by official documentation/API references, not just marketing claims.

- **Company:** TypeSafe AI (typesafe.ai), seed-stage, San Francisco (in-person, near Embarcadero). Team from OpenAI, Google Brain, Meta/FAIR, Stripe, Airbnb, Plaid, Docker. [Team page](https://typesafe.ai/team)
- **Founders:** Diogo Almeida (CEO; ex-OpenAI, ex-Google Brain; co-inventor of RLHF / senior author-line contributor to InstructGPT), Erik Gafni, Sasha Sheng. [HN hiring post by TypeSafeKev, 2026-07-15](https://news.ycombinator.com/item?id=44567324) (via Algolia), [HN comment by KoftaBob, 2026-09-19](https://hn.algolia.com/api/v1/search?query=%22Diogo%20Almeida%22)
- **Launch:** HN launch post 2026-09-15 ("Introducing System One Models and Jev", 1,932 points, 509 comments). Two years in stealth prior. [HN story 49717558](https://news.ycombinator.com/item?id=49717558), [announcement blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- **Product:** Jev is a hosted model behind a single endpoint, `POST /v1/systemone`. Request = `state` (string/JSON object/array, text only) + `model` + a map of typed "questions". Response = one typed answer per question. [API reference](https://docs.typesafe.ai/api)
- **Three question primitives** (mixable in one call, all evaluated in parallel and independently against the same state):
  - **Choice** — pick one of up to **255 options**; returns `choice`, full `probabilities` distribution (sums to 1), `confidence`.
  - **Score** — rate against an ordered rubric of **2–10 levels**; returns probability-weighted `score` (can land between levels), `legend`, `probabilities`, `confidence`.
  - **Noul** — yes/no; returns `noul`, the probability the answer is yes (0–1). No separate confidence.
  [Primitives](https://docs.typesafe.ai/primitives), [API reference](https://docs.typesafe.ai/api)
- **Confidence** is not separately predicted; it is a statistic *derived from* the answer's own probability distribution (peakedness). [Confidence docs](https://docs.typesafe.ai/confidence)
- **Current model version:** `jev-1.13.0`; aliases `jev-latest` and `jev-preview` (both currently point to 1.13.0). Same weights serve every account; **no fine-tuning/LoRA on customer data**. [Models docs](https://docs.typesafe.ai/models)
- **Limits:** 64k tokens total per request; 32k for state + longest single question. Rate limits 250,000 tokens/sec and 1,200 requests/min. Text-only input (no image/audio/video). English is the primary training language; other languages "handled but not equally well". [Models docs](https://docs.typesafe.ai/models)
- **Pricing:** $42 per billion input tokens ($0.042/MTok); output tokens free. Charged per input token only. [Models docs](https://docs.typesafe.ai/models), [home page](https://typesafe.ai)
- **Data policy:** Not trained on customer requests/responses; zero data retention (ZDR) available for enterprise; DPA/MCA/privacy policy published. [Legal](https://docs.typesafe.ai/legal), [Models docs](https://docs.typesafe.ai/models)
- **Access:** Early access via waitlist at console.typesafe.ai (email-code login). SDKs: Python (`typesafe_sdk`, sync + async clients) and JavaScript/TypeScript. Also available via Vercel AI Gateway (per HN commenter with access). Agent skill for Claude Code/Codex published. [Console](https://console.typesafe.ai/), [SDK docs](https://docs.typesafe.ai/sdk), [agent skill](https://docs.typesafe.ai/agent-skill), [HN comment by porridgeraisin](https://news.ycombinator.com/item?id=49717558)
- **System One LLM wrapper:** open-source `system-one-adapter-python` — a drop-in `TypeSafeClient` replacement backed by OpenAI/Anthropic-compatible LLM APIs, used to benchmark LLMs on the same API contract (structured outputs mode or JSON-prompt mode; `llm_answer_mode` probabilities|discrete; probability normalization; malformed-output retries; full attempt logging). [GitHub: typesafe-ai/system-one-adapter-python](https://github.com/typesafe-ai/system-one-adapter-python)
- **Naming:** "System One" after Kahneman's System 1 (fast/intuitive); "Jev" after William Stanley Jevons (Jevons paradox — efficiency drops cost, increases demand). [Blog FAQ](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

## 2. Claims with evidence

Evidence here means "TypeSafe published artifacts/numbers"; it is still mostly self-published.

- **Speed:** 70–500ms end-to-end per call; 40x–200x faster than frontier LLMs "for the same levels of frontier intelligence for System One shaped queries". Evals run "from our laptops on the West Coast" where the service is hosted. [Blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- **Workflow evals (evals.typesafe.ai):** 4 published workflows, each a fixed compute graph in code; reference answers = average of GPT-6 Astra and Fable 5.1 probabilities; LLMs run through the System One LLM wrapper in both "workflow" and single-"prompt" modes. Jev's published numbers:
  - **Customer Service:** Jev 76.0% acc · $0.0001/case · 0.4s. Best LLM workflow: sol 78.3% · $0.0323 · 10.1s. [customer_service.html](https://evals.typesafe.ai/customer_service.html)
  - **Agent Trace Observability:** Jev 71.6% · $0.0003 · 0.5s. Best: sol 76.6% · $0.0575 · 40.3s. [agent_trace_observability.html](https://evals.typesafe.ai/agent_trace_observability.html)
  - **Invoice Processing:** Jev 61.8% · $0.0011 · 0.5s — **notably behind** sol 79.1% and opus 5 78.4% (workflow modes). [invoice_processing.html](https://evals.typesafe.ai/invoice_processing.html)
  - **Security Incidents:** Jev 61.7% · $0.0001 · 0.3s. Best: opus 5 66.2% workflow. [security_incidents.html](https://evals.typesafe.ai/security_incidents.html)
  - **Headline "193.6x faster / 444.6x cheaper"** comes from these workflow evals; TypeSafe itself says these are "on the higher end of real world gains". Home-page example: $0.000081 / 0.114s vs LLMs $0.013880 / 8.566s. [Blog nuance section](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [home](https://typesafe.ai)
  - **Key observation: Jev is NOT the accuracy leader on any of the 4 published workflows** — it sits on the cost/latency Pareto frontier with competitive-but-not-top accuracy (71.6–76.0% vs best-LLM 66.2–79.1% depending on workflow).
- **Disclosed eval biases (by TypeSafe itself):** workflows built by their own model-capabilities team ("some bias could exist"); reference = average of Astra + Fable 5.1 biases toward OpenAI/Anthropic and "likely underestimates" Jev and DeepSeek; wrapper is slower/more expensive than unstructured LLM calls; hallucination-rate numbers for LLMs come from OpenRouter (routing bias); Jev's 0% type-error figure is "not empirical" but "mathematically impossible" by schema construction. [Blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- **Demos:** Doom bot at ~10 queries/sec (~$7/hour) on text-structured game state (not pixels); Wikiracing with cardinality ≤255 and a 2-stage score-then-choose fallback for higher cardinality; side-by-side vs GPT-5.6 Terra. [Blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- **Known-failure disclosure ("jaggedness"):** official list of 9 failure modes for jev-1.13 — literal reading, math/counting/numeric representations (hex colors, RGB), date/time comparison, multi-hop indirection, large noisy states, adversarial content in state, contradictory instructions/criteria, non-guaranteed structural invariants (e.g. P(noul) + P(not-noul) can sum to 1.19; Noul vs Choice thresholds not transferable), and no text generation. [Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
- **Cookbooks with measured results:** e.g. 13-question GDPR briefing in one call = 12.2x cheaper / 10.0x faster with identical answers; CLERC legal re-ranking top-1 5%→18%, top-10 38%→62%; 218-line semantic search in one request; 182-skill ranking; 450-pair entity alignment; 75-class SEC classification with confidence-gated fallback. [llms.txt cookbook index](https://docs.typesafe.ai/llms.txt)
- **Independent replication (Southbridge):** entity resolution on Ohio campaign-finance data — Jev-only arm: 1 mistake + 4 abstentions of 200 families, 3.37¢, 56s; Jev + 5 Luna reviews: within 0.5pp of Fable at 226x lower cost, 7.35x throughput; Fable-only: $9.83, 845s. Extrapolated 1TB: Fable $8.16M vs Jev+Luna $36.1k. [southbridge.ai blog, 2026-09-20](https://www.southbridge.ai/blog/jev-entity-resolution)
- **Independent replication (Sean Goedecke):** rebuilt "System One" behavior on Qwen3-8B in ~150 lines via single-token constrained generation + prefill; Doom at 190ms loop on H100; Wikiracing needed tournament sampling (2-stage scoring "did not work very well" for him — suggests Jev's trained confidence estimates carry real weight). [seangoedecke.com, 2026-09-18](https://www.seangoedecke.com/two-techniques-for-working-with-system-one-models/)

## 3. Claims without evidence (or contested)

- **"Can't hallucinate" / "Zero Hallucinations":** contested semantics. TypeSafe's own nuance: schema-matching is guaranteed, but correctness is not. HN (jacobgold, adroitboss, Goedecke): Jev can still pick a wrong valid value; "can't hallucinate" reduces to "can't emit an out-of-schema value". [Home](https://typesafe.ai), [HN thread](https://news.ycombinator.com/item?id=49717558), [Goedecke](https://www.seangoedecke.com/jev-means-structured-output-is-interesting-again/)
- **"Calibrated probabilities" via RLCD:** no published calibration curves, ECE/Brier numbers, or methodology for Jev. Docs define calibration aspirationally ("outcomes assigned 0.8 should occur ~80% of the time") but publish no measurements. [AI primer](https://docs.typesafe.ai/introduction/machine-learning-primer)
- **"Similar levels of intelligence" to frontier LLMs on System One tasks:** supported only by the 4 self-built workflow evals, where Jev is actually *behind* the best LLM on all four (by 0.7–17.3pp). No public-benchmark numbers by deliberate policy. [Blog FAQ](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [antibenchmaxxing post](https://typesafe.ai/blog/antibenchmaxxing)
- **Pricing sustainability:** TypeSafe concedes "we can't prove it isn't subsidized". Home FAQ asks "Are these prices temporary or subsidized?" (answer not recoverable from static HTML). [Blog](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- **"New model architecture" / "parallel sampler" / "hardware-aware":** asserted, never described. No paper, no parameter count, no diagram. Team member (CompleteSkeptic, i.e. Diogo's public persona — same "bitterest lesson" text appears on both completeskeptic.com and typesafe.ai) said on HN: "architecture is close to the chest for now, but we have talked about writing a paper… data is probably far more interesting than architecture." [HN thread](https://news.ycombinator.com/item?id=49717558), [completeskeptic.com/p/the-bitterest-lesson](https://www.completeskeptic.com/p/the-bitterest-lesson)

## 4. Undisclosed details (the gaps)

- **Architecture:** undisclosed. HN speculation: encoder-only-ish transformer with scalar/ordinal heads (quotemstr, krackers); diffusion (Goedecke reports hearing this); MoE (claimed without source in the third-party Von benchmark table: "TypeSafe Jev — Proprietary MoE"). TypeSafe FAQ says only "Jev is neither small nor an LLM". [Von repo](https://github.com/wfzyx/von), [HN thread](https://news.ycombinator.com/item?id=49717558)
- **Model size / parameter count:** undisclosed. ("Neither small nor an LLM" is the only official statement.)
- **RLCD algorithm:** only the objective is described (reward calibrated probability distributions, not preferred text). HN commenter porridgeraisin (waitlist user) describes it as strongly penalizing confident-wrong distributions — "a known existing thing variously called calibrated RL" — and notes the acronym RLCD has 3 unrelated expansions in the literature. No paper, no loss function, no training details from TypeSafe.
- **Training data:** "We make all the data ourselves… TypeSafe is primarily a data research lab." Synthetic-data emphasis corroborated by their July 2026 hiring post ("Member of Technical Staff, Synthetic Data (multiple needed)"). Nothing else disclosed. ## 5. Independent reactions & open questions

**Hacker News main thread** (1,932 pts, 509 comments, 2026-09-15): [link](https://news.ycombinator.com/item?id=49717558)
- Skepticism of apples-to-oranges speed comparisons: "If Jev is skipping generation entirely for a narrow structured task, of course it's faster" (ramon156); "speed comparison seems misleading… Jev can only generate structured output" (jacobgold).
- Skepticism of no-public-benchmarks stance: "lol, I bet they would publish them if their score on those benchmarks were good" (jceg).
- Moat doubts: "isn't hard to turn any LLM into a System One model" via prefill + single constrained token (Goedecke; demonstrated with Qwen2.5-1.5B 2–3x speedup, and Qwen3-8B Doom/Wikiracing replications). Prediction: labs will ship "System One Terra / System One Haiku" if Jev gets traction.
- Capability ceiling doubt: no test-time compute ⇒ capped around non-reasoning-LLM strength (Goedecke).
- Practical adoption friction: desire for OpenRouter/AWS Bedrock distribution to avoid vendor review (mushufasa); Jev is on Vercel AI Gateway per one user.
- Open research questions raised by practitioners: how to implement high-cardinality choice (labels vs indexes — Goedecke found labels beat indexes on Wikiracing); how OOD behavior differs from LLMs ("theoretically worse, practically depends on their method" — porridgeraisin); calibration-threshold accuracy/automation trade-off curves ("what % of decisions can we automate at 90% accuracy?" — ActivePattern); structural non-invariance across question formulations (TypeSafe's own jaggedness doc).

**Independent tests:**
- **Mikulski (2026-09-19):** 400 Quick-Draw! doodles as SVG text, 10-way Choice. Jev 35% (vs Sonnet 5 on same SVG 57%, Sonnet on image 91%, Jev on base64 ≈ chance 9%). Massive response bias: answered "airplane" for 209/400; 0/40 cats. Conclusion: real signal from coordinates but far below an LLM on out-of-distribution numeric-ish input; "System One models don't explain their reasoning." [mikulskibartosz.name](https://mikulskibartosz.name/typesafe-jev-guess-what-i-drew)
- **Southbridge (2026-09-20):** production entity resolution — strong positive result with careful criterion-writing; warns "applying the wrong signal or prompting the wrong way causes large mistakes at scale"; near-tie probabilities (0.53) became wrong answers when the pipeline consumed labels without probability gating. [southbridge.ai](https://www.southbridge.ai/blog/jev-entity-resolution)
- **Von (wfzyx/von, 2026-09-21):** open-source local drop-in alternative — 395M-param bidirectional ModernBERT, "RLCD" reimplemented as CE + Brier loss + temperature scaling (T=1.1692), trained on ~290k examples (ANLI/WANLI/MultiNLI/SNLI + domain sets), full `/v1/systemone` wire compatibility. Claims 71.5% macro on a 49-task "jabr v2" suite vs Jev's 96.6%, and beats Jev on zero-shot ViZDoom (9.38 vs 5.62 kills) at ~18ms local vs ~115ms API. Notable: it *defines* confidence as P(top1)−P(top2) and cites an arXiv paper for "RLCD = Reinforcement Learning with Calibration Distribution" (arXiv:2503.23303) — i.e., the ecosystem is already concretizing what TypeSafe left vague. [github.com/wfzyx/von](https://github.com/wfzyx/von)
- **Cua (2026-09-18):** announced "Cua S1 — a family of System One models" (fast-follow competition). [via HN](https://hn.algolia.com/api/v1/search?query=%22System%20One%20Models%22)
- **Media/talks:** YouTube interview "Jev CEO: I made ChatGPT, now I'm building What's Next" (2026-09-17) [youtube](https://www.youtube.com/watch?v=cJ0EOzey--o); Google Doc circulating on HN: "Diogo Almeida: Thoughts on a Typesafe Coding Agent" (2026-09-21).

## 6. API & integration surface (what a developer actually does)

1. Get early access (waitlist → console.typesafe.ai), create API key; or use Vercel AI Gateway.
2. `pip install typesafe_sdk` (Python) or JS SDK; `TypeSafeClient()` with `client.system_one(state=..., questions={...})`. [Quickstart](https://docs.typesafe.ai/introduction/quickstart)
3. Author **questions**: each has an id, `type` (choice/score/noul), `instructions` (string or structured object with backtick path-references into state), and `criteria` (option→description map for Choice ≤255; ordered levels for Score 2–10; optional yes/no glosses for Noul). Question keys are not sent to the model. [API reference](https://docs.typesafe.ai/api)
4. Fan out many questions per call (parallel, independent, near-constant latency; "speculative fan-out" pattern); compose answers in ordinary code (thresholds on probabilities/confidence, weighted composite scores, confidence-gated routing to humans or bigger LLMs). [Patterns](https://docs.typesafe.ai/patterns)
5. Keep arithmetic, counting, dates, and exact matching in code (per jaggedness doc); decompose multi-factor judgments into atomic questions; second request only when a later question genuinely depends on an earlier answer.
6. Benchmark an LLM on the same contract with the open-source `system-one-adapter` (OpenAI/Anthropic/custom endpoints), which logs every attempt, retries malformed structure, and normalizes invalid probability distributions. [GitHub](https://github.com/typesafe-ai/system-one-adapter-python)
7. Optional: install the TypeSafe agent skill for Claude Code/Codex (`/typesafe:typesafe-ai`) so coding agents can write TypeSafe integrations. [Agent skill](https://docs.typesafe.ai/agent-skill)
