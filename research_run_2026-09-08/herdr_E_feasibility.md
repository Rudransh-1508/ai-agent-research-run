# Agent E — Experimental Feasibility Audit

**Cut-off:** 8 September 2026  
**Scope:** public environments, code, data, checkpoints, and evaluation protocols for decentralized planning, ad hoc teamwork, strategic communication, norms/reputation, shared memory, LLM teams, and oversight.  
**Audit boundary:** this is an artifact and design audit, not a claim that every repository was installed or that every published number was reproduced locally.

## Executive verdict

There is enough public infrastructure to run a credible experimental paper without building a new omnibus environment. The feasible spine is: exact small Dec-POMDPs for ground truth; OvercookedV2 plus a public partner zoo for ad hoc teamwork; OpenSpiel/SILO-BENCH for controlled communication; GovSim or RepuNet for institutions; a deterministic Caura fault harness for shared memory; Alem for ecological LLM-team transfer; and Who&When plus conformal attribution for oversight.

The main constraint is not environment availability. It is comparability. Several attractive setups change the information structure, action cost, horizon, or verifier access between baselines. Full-scale Cicero training, full Melting Pot population learning, 100-agent SILO runs, and 10,000-step hosted-LLM Alem episodes are not realistic for a small research run. They are reference ceilings or transfer tests, not default experiments.

**Recommended status:**

| Family | Experimental value | Feasibility now | New benchmark needed? |
|---|---|---:|---|
| MADP exact Dec-POMDPs | Exact decentralized and centralized reference values | **High for tiny instances; low for scaling** | Wrapper/protocol only |
| OpenSpiel games | Controlled imperfect information, signaling, bargaining | **High** | LLM text adapter if language is central |
| Overcooked / OvercookedV2 / ZSC-Eval | Ad hoc teamwork and unseen partners | **High for evaluation** | No |
| Melting Pot 2.0 | Social generalization, mixed motives, unfamiliar partners | **Medium for evaluation; low for new training** | No |
| Cicero Diplomacy | Strategic language, deception, alliance formation | **Low for reproduction; medium for checkpoint evaluation** | No |
| GovSim | LLM commons governance and sustainability | **Medium-high** | No |
| RepuNet / LR2 / MAC-SPGG | Reputation, norms, incentives | **Medium** | Only for unreliable blame/shared-memory coupling |
| SILO-BENCH | Distributed computation under information silos | **High at 2–10 agents** | No |
| Alem | Long-horizon LLM/MARL coordination with communication and memory | **Medium for a capped pilot** | No |
| Caura/MemClaw | Governed shared fleet memory | **High for systems faults** | Yes for strategic maintenance incentives |
| Who&When + conformal attribution | Offline team oversight and calibrated rollback | **High** | Yes for live strategic adaptation |
| TeamBench | Planner–Executor–Verifier marginal value | **Medium; preprint artifact** | No for role ablation; yes for multi-round oversight |

## Audit method and evidence standard

I counted a source only when it was an author/venue-controlled paper record, official repository, official dataset, or official checkpoint release. Search aggregators and the local survey corpus were used only to locate candidates. Counts do not merge a paper with its code repository because they are distinct reproducibility artifacts.

Labels used below:

- **Verified public:** the official URL resolves and exposes the claimed artifact or protocol.
- **Published cost:** stated by the source.
- **Auditor estimate:** a transparent call/episode bound derived from the public configuration, not a measured runtime.
- **Unknown:** the public artifact does not provide a defensible number; no number is invented.

## Serious experimental families

### F1. Exact decentralized planning: MADP + FB-HSVI benchmark instances

- **Agents/count:** mostly two-agent discrete Dec-POMDPs: Dec-Tiger, Broadcast Channel, Recycling Robots, Grid-Small, Box Pushing, Mars Rovers, and Fire Fighting variants in the [MADP problem directory](https://github.com/MADPToolbox/MADP/tree/master/problems).
- **Observations:** private discrete observations generated by the model's observation kernel; local history only at execution.
- **Actions:** model-specific discrete local actions; the environment applies the joint action.
- **Communication:** none unless explicitly encoded in the model. Offline centralized policy computation is legal; runtime state sharing is not.
- **Objective:** maximize finite-horizon expected cumulative team reward. [FB-HSVI](https://jair.org/index.php/jair/article/view/10986) supplies optimality-guaranteed reference values for several standard instances.
- **Must-beat baselines:** random local policy; independent/myopic policy; published or recomputed decentralized optimum `V*_Dec`; centralized POMDP/MPOMDP optimum `V*_Cent`; exact evaluation of any submitted policy tree/FSC.
- **Metrics:** raw return; exact policy value; `(V*_Dec - V)/(|V*_Dec|+eps)`; decentralization gap `V*_Cent-V*_Dec`; information-legality violations; policy size; solver wall time and bound gap.
- **Ablations:** horizon, observation noise, reward coupling, state/action cardinality, communication bit budget, shared randomness, team size where a model exists.
- **Compute/runtime:** loading and evaluating fixed tiny policies is CPU work and should be seconds-to-minutes. Exact solving is NEXP-complete and becomes the bottleneck rapidly; published small-instance values should be reused rather than pretending that arbitrary horizons are tractable. The public MADP code is old C++/Autotools and was last updated in 2020.
- **Public code/data:** [MADP Toolbox](https://github.com/MADPToolbox/MADP), GPL-3.0; model files are committed.
- **New benchmark need:** **no** for the mathematical experiment. **Yes, a thin adapter** for text observations/actions, policy-schema validation, and exact policy evaluation if LLMs are asked to synthesize controllers.
- **Feasibility warning:** do not label Monte Carlo return as an exact value, and do not compare an LLM with shared global state to `V*_Dec`. The information structure is the experiment.

### F2. Controlled strategic communication: OpenSpiel

- **Agents/count:** two-player and n-player games. Relevant built-ins include `lewis_signaling`, `trade_comm`, `negotiation`, `bargaining`, Hanabi, Sheriff, auctions, poker, social dilemmas, and repeated games.
- **Observations:** game information states or observations; private types/cards plus public action history where defined.
- **Actions:** finite game actions, offers, signals, trades, bids, or moves.
- **Communication:** explicit message/signal actions in the communication games; implicit signaling through actions elsewhere.
- **Objective:** player utility in cooperative, zero-sum, or general-sum extensive-form games.
- **Must-beat baselines:** uniform random; tabular best response; CFR/CFR+ or exploitability-minimizing policies where applicable; truthful and babbling equilibria for signaling; scripted reciprocity; no-communication counterpart.
- **Metrics:** expected utility/social welfare; exploitability/NashConv; Pareto efficiency; agreement rate; truthfulness/calibration by private type; message entropy and mutual information; regret; out-of-distribution partner payoff.
- **Ablations:** remove messages, permute semantics, cap alphabet/bits, add message cost/noise/delay, change partner policy, private-information quality, repeated versus one-shot play.
- **Compute/runtime:** small tabular games and equilibrium baselines are commodity-CPU experiments. Large games such as full Diplomacy are outside this claim.
- **Public code/data:** [OpenSpiel](https://github.com/google-deepmind/open_spiel), Apache-2.0, C++/Python; many reference algorithms are included.
- **New benchmark need:** **only if free-form language is load-bearing.** A minimal LLM adapter should preserve the same game state and message budget; a new game engine is unnecessary.
- **Feasibility warning:** natural-language fluency is not strategic communication. Require messages to predict private state or causally improve utility under a matched channel budget.

### F3. Ad hoc teamwork: Overcooked-AI, OvercookedV2, and ZSC-Eval

- **Agents/count:** two cooperative cooks. Evaluate a focal policy against unseen AI or human-proxy partners; OvercookedV2 adds partial observability and stochasticity.
- **Observations:** grid state or partial local view, held object, objects/appliances, orders, teammate position/action history; representation depends on implementation.
- **Actions:** north/south/east/west, stay/interact (six primitive choices in the common implementations).
- **Communication:** no native language channel in the core benchmark; coordination is behavioral. External chat changes the task and must be a separate condition.
- **Objective:** maximize delivered-soup reward within a fixed horizon across layouts.
- **Must-beat baselines:** self-play, random, behavior cloning/human proxy, population-based training, Fictitious Co-Play, MEP, COLE; ZSC-Eval partner pools with BR-Div/BR-Prox; a centralized joint planner only as a ceiling.
- **Metrics:** episode return, soups/orders completed, time-to-delivery, collisions/idle time, partner-normalized return, worst-partner/CVaR return, cross-layout and cross-partner generalization.
- **Ablations:** unseen partner versus self-play partner; side/start position; layout; observation radius/noise; stochastic recipes/order queues; partner switch mid-episode; with/without a short adaptation history.
- **Compute/runtime:** [Overcooked-AI](https://github.com/HumanCompatibleAI/overcooked_ai) unit tests report 5–10 minutes for the full accessory suite; fixed-policy evaluation is light. Training modern ZSC populations is GPU work but can be avoided using the [ZSC-Eval policy pool](https://huggingface.co/Leoxxxxh/ZSC-Eval-policy_pool) linked by the official toolkit. JaxMARL gives vectorized GPU training if new policies are essential.
- **Public code/data:** [Overcooked-AI](https://github.com/HumanCompatibleAI/overcooked_ai); [JaxMARL](https://github.com/bold-lab-ai/JaxMARL) with OvercookedV2; [ZSC-Eval](https://github.com/sjtu-marl/ZSC-Eval); [COLE platform/checkpoint instructions](https://github.com/liyang619/COLE-Platform).
- **New benchmark need:** **no.** Add a partner-switch schedule and a locked evaluation manifest.
- **Feasibility warning:** legacy `human_aware_rl` BC/PPO code is deprecated; the COLE repository also warns that code and checkpoint layout names differ. Pin commits and record the mapping.

### F4. Social generalization and mixed motives: Melting Pot 2.0

- **Agents/count:** substrate-dependent multi-agent populations, with focal agents evaluated among fixed background populations; over 50 substrates and over 256 scenarios are public.
- **Observations:** egocentric RGB/feature observations from Lab2D plus substrate-specific inventory/status.
- **Actions:** movement, rotation, interaction and substrate-specific beams/actions.
- **Communication:** normally environmental/behavioral rather than unrestricted language; substrate-specific signals may exist.
- **Objective:** individual returns under cooperative, competitive, and mostly mixed-motive games; evaluation asks whether focal agents generalize to unfamiliar social partners.
- **Must-beat baselines:** random; independent PPO starter; report baselines ACB, V-MPO, OPRE; hard-coded policies where relevant; exploiter trained on evaluation scenarios only as an optimistic normalization reference.
- **Metrics:** per-capita focal return by scenario; normalized score; social-welfare and equality/sustainability measures appropriate to each substrate; worst-scenario performance; partner generalization gap.
- **Ablations:** familiar/unfamiliar background population; symmetric/asymmetric roles; focal population size; reward sharing; partner composition; observation channel; substrate families.
- **Compute/runtime:** environment smoke/evaluation is feasible where a `dmlab2d` wheel exists. Serious new population learning is expensive: the 2023 contest offered up to **$50,000 in compute support**, a useful warning against treating full reproduction as a laptop run. The included RLlib trainer is explicitly illustrative, not the authors' baseline recipe.
- **Public code/data:** [official Melting Pot repository](https://github.com/google-deepmind/meltingpot), PyPI package `dm-meltingpot`, evaluation notebook and SavedModel interface.
- **New benchmark need:** **no** for social generalization. **Yes** only for a controlled free-form language layer.
- **Feasibility warning:** scores normalized between random and an evaluation-scenario exploiter are not fractions of an optimal policy. Do not call them optimality gaps.

### F5. Strategic natural language: Cicero Diplomacy

- **Agents/count:** seven powers; public comparison supports one Cicero agent versus six imitation agents or shared-agent self-play.
- **Observations:** board state, phase/order history, private bilateral dialogue and negotiation context.
- **Actions:** private messages plus simultaneous Diplomacy orders for units.
- **Communication:** unrestricted bilateral natural language; persuasion, promises, alliances, omission, and deception are endogenous.
- **Objective:** supply-center control/game score; the board has 34 supply centers and a solo win requires more than half.
- **Must-beat baselines:** imitation-only agent; no-press strategic agent/Diplodocus; no-dialogue ablation; shared-agent self-play; human/game records for ecological reference.
- **Metrics:** game score/supply centers, win/draw rate, order support and agreement fulfillment, message truth/consistency, exploitability proxy, alliance stability, calibrated intent prediction.
- **Ablations:** dialogue versus no press; planning versus imitation-only; truthful-only decoding; one-versus-six role; power assignment; model checkpoint; private-message budget.
- **Compute/runtime:** **full reproduction is infeasible for a small run.** Official RL commands request 256 GPUs; local training is described as possible on an 8-GPU-or-more machine but very slow. Evaluation also has a substantial model-memory burden.
- **Public code/data:** [Cicero repository](https://github.com/facebookresearch/diplomacy_cicero), archived/read-only since 17 April 2025; pretrained files are downloadable, model weights are CC-BY-NC, and redacted consented games are included.
- **New benchmark need:** **no.** Use it only as a transfer test after controlled signaling results.
- **Feasibility warning:** the human supervised dialogue/game dataset is not public, so supervised training cannot be reproduced. The code pins Python 3.7, PyTorch 1.7.1, CUDA 11 and brittle protobuf patches.

### F6. Norm emergence and commons governance: GovSim

- **Agents/count:** five LLM agents per simulation in the paper; three common-pool-resource scenarios (fishery, pasture, pollution), 15 tested LLMs, 45 model–scenario instances.
- **Observations:** textual private/public situation, current resource consequences, agent memory and prior interactions; exact contents depend on phase/configuration.
- **Actions:** harvest/use the resource, converse, propose plans, and reflect; the environment applies resource regeneration/depletion.
- **Communication:** natural-language group conversation and reflection. The public repository also supports heterogeneous model assignment.
- **Objective:** avoid collective collapse while obtaining resources; sustainability and individual utility can conflict.
- **Must-beat baselines:** default agents; no-language; universalization prompt; greedy newcomer; scripted sustainable quota; centralized sustainable controller; fixed-message-budget condition.
- **Metrics:** survival/collapse, resource stock trajectory, efficiency, equality/Gini, individual return, over-extraction, message/token cost, newcomer recovery.
- **Ablations:** no language; no reflection/memory; universalization; heterogeneous models; greedy outsider; concurrent versus sequential harvesting; resource regeneration and scarcity.
- **Compute/runtime:** no defensible wall-time is published. A run makes multiple LLM calls per agent per round, plus optional conversation/reflection, so log calls and tokens before scaling. Start with one scenario, five agents, six rounds, and one seed; expand only after deterministic replay and parse-rate checks.
- **Public code/data:** [GovSim](https://github.com/giorgiopiatti/GovSim), MIT, Hydra configurations, prompts, analysis and AMD reference Dockerfile.
- **New benchmark need:** **no** for sustainability/norm experiments. A new environment is needed only if private noisy blame or strategic memory maintenance is the research object.
- **Feasibility warning:** the headline 43 collapses out of 45 model–scenario instances is descriptive, not 45 independent replications. Model identity, scenario, and seed must not be conflated.

### F7. Reputation, learned norms, and contribution incentives: RepuNet, LR2, MAC-SPGG

This family is experimentally serious but contains three different objects; they should not be reported as one benchmark score.

| Item | RepuNet | LR2 | MAC-SPGG |
|---|---|---|---|
| Agents/count | 20 LLM agents, initially isolated | spatial MARL population, local four-neighbor interactions | 3 heterogeneous LLM agents |
| Observations | direct encounters, gossip, self/peer reputation, network neighborhood | local dilemma state, neighbor behavior/reputation, local rewards | none/prior contributions; partial mode exposes only the immediately preceding contribution, full exposes all prior contributions |
| Actions | dilemma/trade/participation choices; update reputations; gossip; create/sever edges | cooperate/defect plus learned reputation evaluation | sequential contribution/generation parameters and final answer |
| Communication | direct encounter + gossip | reputation signal/environmental interaction | predecessor outputs, not free chat |
| Objective | sustain cooperation in Prisoner's Dilemma, voluntary participation and investment | individual objective shaped by learned reputation reward | task quality minus effort cost plus public-good incentives |
| Public artifacts | [RepuNet code](https://github.com/RGB-0000FF/RepuNet), [AAMAS paper](https://www.ifaamas.org/Proceedings/aamas2026/pdfs/UEHN4980.pdf) | [LR2 code](https://github.com/itstyren/LR2), [AAMAS paper](https://www.ifaamas.org/Proceedings/aamas2025/pdfs/p1745.pdf) | [MAC-SPGG code/checkpoint](https://github.com/YunhaoLiang/MAC-SPGG), [AAMAS paper](https://www.ifaamas.org/Proceedings/aamas2026/pdfs/SJPO2377.pdf) |

- **Must-beat baselines:** no reputation; direct-only reputation; gossip-only; random rewiring/exclusion at matched rate; fixed social norms; oracle behavior labels; no incentive; equal token/compute single-agent and sequential ensemble.
- **Metrics:** cooperation and welfare; network assortativity/modularity; exclusion precision; reputation–behavior correlation/calibration; false gossip propagation; equilibrium gap/free-riding rate; task accuracy and total tokens.
- **Ablations:** reputation, gossip, rewiring, identity persistence, observation noise, Sybils, delayed blame, sanction severity, order of contributors, partial/full predecessor visibility, evaluator replacement.
- **Compute/runtime:** RepuNet uses GPT-4o-mini, five repetitions and scenario-dependent stopping after cooperation stabilizes; public quick start is five steps. LR2 requires PyTorch training but supports CPU/GPU. MAC-SPGG includes a 3 MB inference checkpoint; local three-model evaluation recommends 30 GB+ VRAM, while API evaluation avoids local model memory.
- **New benchmark need:** **yes** for *sanctioning under unreliable blame* because these systems generally observe direct behavior or define the reward signal. **Yes** for strategic reputation poisoning. Otherwise, no.
- **Feasibility warning:** RepuNet's variable stopping rule can bias comparisons if treatments stabilize at different times; preregister a fixed horizon. Reputation generated by the same LLM that benefits from it is not ground truth. MAC-SPGG's “unique SPNE” is conditional on tuned mechanism parameters and does not establish truthful effort measurement.

The 2026 [collective norm-formation CPR framework](https://www.ifaamas.org/Proceedings/aamas2026/pdfs/CZDC3237.pdf) is also relevant: ten agents choose effort, punishment, social learning and propose→vote norms, with two API calls per agent per norm-voting round. No public code was located on its official paper record, so it is a design reference, not a primary runnable environment.

### F8. Distributed information and communication protocols: SILO-BENCH

- **Agents/count:** 2, 5, 10, 20, 50, or 100 role-free agents, each holding one private shard.
- **Observations:** task instructions plus only the agent's local data shard and received messages/files from prior synchronized rounds.
- **Actions:** compute locally; send/receive/wait/submit under P2P or broadcast; list/read/write/delete/wait/submit under shared-file-system (SFS).
- **Communication:** P2P, broadcast, or shared files; round-`t` writes become visible in round `t+1`.
- **Objective:** all agents converge on the exact answer to 30 algorithmic distributed-computation tasks across aggregation, mesh and global-shuffle complexity.
- **Must-beat baselines:** single agent with all shards; single agent under matched context; deterministic distributed algorithm; no communication; random topology; published protocols; compute/token-matched larger model.
- **Metrics:** success rate, partial correctness, token consumption, communication density; add wall time, bytes/message, information acquired versus integrated, and per-agent disagreement.
- **Ablations:** protocol; agent count; task level; message size; rounds; synchronized versus asynchronous delivery; private scratchpad; role prompt; shared-file locking; adversarial/missing worker.
- **Compute/runtime:** public release includes 180 pre-generated JSONs (30 task types × six scales), generators, and a default cap of 100 rounds. The paper reports 54 configurations and 1,620 experiments across three models. A full 100-agent API sweep is not economical. A pilot with 2/5/10 agents, 20 rounds and one model should precede any scale claim.
- **Public code/data:** [ACL paper](https://aclanthology.org/2026.acl-long.1354/); [official repository](https://github.com/jwyjohn/acl26-silo-bench), Unlicense.
- **New benchmark need:** **no** for information silos. **Yes** for strategic lying, persistent reputation, or memory provenance because current tasks are cooperative and exact-answer based.
- **Feasibility warning:** `SFS` is a communication protocol, not automatically shared memory: without persistence across episodes, ownership, provenance, or stale-state tests, a “memory commons” claim is unsupported.

### F9. Open-ended LLM teams: Alem

- **Agents/count:** tested default is three agents (config supports 1–4) with warrior/forager/miner-like soft specialization.
- **Observations:** each agent's egocentric symbolic, pixel, or text view; text includes local objects, coordinates, coordination affordances, teammates, health/status, inventory and legal actions.
- **Actions:** 55 text-mapped canonical actions including movement, `Do`, crafting, casting, request/give/build; invalid text defaults to `Noop`.
- **Communication:** LLM agents broadcast up to 400 characters alongside every action and maintain a private scratchpad; MARL agents instead spend an action to emit one of a small number of discrete signals.
- **Objective:** survive, explore, craft, trade, fight and complete 93 achievements including 27 coordination goals over nine dungeon levels.
- **Must-beat baselines:** random/dummy; single-agent experimental variant only as a diagnostic; IPPO, no-parameter-sharing IPPO, HyperMARL-IPPO, MAPPO, PQN-VDN; no-communication, no-scratchpad, generic-prompt, and non-specialized LLM conditions.
- **Metrics:** team/normal/coordination achievement percentage; per-agent achievement; episode return/length; trade/revive counts; handover completion; parse rate; calls/tokens/wall time.
- **Ablations:** communication, scratchpad, prompt knowledge, CoT, specialization, shared reward, difficulty, agent count, history length, text versus symbolic/pixels.
- **Compute/runtime:** CPU one-step smoke incurs about 30 seconds on first JAX compilation. Public RL release contains 120 checkpoints = 2 budgets (100M, 1B steps) × 4 algorithms × 3 difficulties × 5 seeds. The default LLM protocol is 20 episodes × up to 10,000 steps × 3 agents = an upper bound of **600,000 model responses per condition**, before retries/debriefs. Use 100–200-step pilots and disable images/debriefs.
- **Public code/data:** [Alem repository](https://github.com/alem-world/alem-env), MIT; [paper](https://arxiv.org/abs/2606.08340); [120 RL checkpoints](https://huggingface.co/alem-world/alem-rl-baselines).
- **New benchmark need:** **no** for ecological transfer. Add deterministic micro-scenarios only if causal communication/memory credit is required.
- **Feasibility warning:** the official documentation says MARL and LLM scores are not directly comparable. MARL communication consumes the action; LLM free-form communication is sent alongside the action. Any head-to-head claim must equalize this cost. Results before and after v0.2.0 are also not directly comparable because ladder placement changed generated worlds.

### F10. Governed shared memory: Caura (formerly MemClaw)

- **Agents/count:** arbitrary fleet; local test should use 2–10 named agents across at least two fleets/tenants. Production-scale claims are not required for the experiment.
- **Observations:** query results filtered by tenant/fleet/agent scope, temporal status, provenance and trust policy.
- **Actions:** write, recall/search, supersede/correct, propagate/share, delete/forget, and policy/credential operations.
- **Communication:** indirect asynchronous communication through persistent memory and MCP/REST, not conversational chat.
- **Objective:** preserve useful cross-agent knowledge while preventing unauthorized leakage, stale propagation, contradiction persistence and provenance collapse.
- **Must-beat baselines:** isolated per-agent memory; ungoverned shared SQLite/JSON store; scope-only access control; provenance-only; temporal supersession-only; full policy; oracle state database.
- **Metrics:** cross-agent task success; recall/precision; stale-answer and contradiction rate; cross-scope leakage; provenance-chain accuracy; write-to-visible/search latency; token savings; repair success; availability under denied writes.
- **Ablations:** scope, trust tier, strong/eventual write, supersession, provenance, duplicate gate, agent credential, delayed worker, malicious writer, Sybil corroboration, read/write concurrency.
- **Compute/runtime:** local standalone Docker starts PostgreSQL 16+pgvector, Redis, storage and API; official quick start says about 30 seconds startup and no model/API key for deterministic keyword tests. Semantic retrieval adds an embedding provider or local embedder. The paper's ArgusFleet results are measurements of a live service, not a comparative benchmark.
- **Public code/data:** [Caura repository](https://github.com/caura-ai/caura), Apache-2.0; [Governed Shared Memory paper](https://arxiv.org/abs/2606.24535).
- **New benchmark need:** **yes** for incentive-compatible memory maintenance or a “memory commons.” Current governance tests are systems/security tests, not a repeated game in which agents bear costs for verifying and repairing shared knowledge.
- **Feasibility warning:** production statements (for example, hundreds of agents and latency figures) are self-reported and should not substitute for local measurements. Standalone auth bypass is unsuitable for isolation experiments.

### F11. Oversight and failure localization: Who&When + conformal attribution

- **Agents/count:** traces from 127 multi-agent systems; the current public Who&When release exposes 184 annotated failed tasks (126 algorithm-generated and 58 hand-crafted).
- **Observations:** complete task, system/agent descriptions, multi-step interaction history and final failure trace.
- **Actions:** an offline overseer predicts the responsible agent and decisive step; conformal methods emit contiguous prediction sets and may select a rollback point.
- **Communication:** no live intervention in the base benchmark; oversight consumes the recorded trace.
- **Objective:** accurately and efficiently localize the causal failure and recover with calibrated coverage.
- **Must-beat baselines:** random agent/step; all-at-once LLM judge; step-by-step judge; binary search; naive node scorer; vanilla conformal, left/right/two-way filters; oracle label; no rollback and full restart.
- **Metrics:** agent-level and step-level accuracy; set coverage, set length/efficiency, abstention; rollback success and recomputation saved; calibration by trace length, role, model and system origin.
- **Ablations:** algorithm-generated versus hand-crafted; trace truncation; hidden agent names/roles; verbosity normalization; evaluator family; calibration-set size; alpha; delayed or partial logs; adversarial self-explanation.
- **Compute/runtime:** dataset parsing/evaluation and conformal phase 2 are CPU/offline. New LLM node scoring is the only API/GPU-heavy phase; cached node scores should be used for method sweeps. The conformal repository explicitly separates model scoring from pure-Python conformal evaluation.
- **Public code/data:** [ICML paper](https://proceedings.mlr.press/v267/zhang25cq.html); [Who&When code](https://github.com/mingyin1/Agents_Failure_Attribution); [Who&When dataset](https://huggingface.co/datasets/Kevin355/Who_and_When); [conformal code](https://github.com/layer6ai-labs/conformal-agent-error-attribution); [conformal paper](https://arxiv.org/abs/2605.06788).
- **New benchmark need:** **yes** for endogenous oversight where agents anticipate audits, hide evidence, alter effort, or change routing. The existing logs are observational and fixed.
- **Feasibility warning:** the published best result (53.5% responsible-agent accuracy, 14.2% decisive-step accuracy) is not deployment-ready. An abstaining conformal set is not the same as correct blame, and coverage on exchangeable offline traces need not survive strategic distribution shift.

### F12. Role-separated task teams and verifier value: TeamBench

- **Agents/count:** three roles—Planner, Executor, Verifier—run in isolated Docker containers; the release contains 931 instances over 851 templates and 19 categories.
- **Observations:** Planner sees full specification but cannot edit; Executor edits/runs code but sees only the plan/brief; Verifier sees full spec and workspace read-only.
- **Actions:** plan file, workspace/tool actions, and verifier attestation. Container mounts enforce access boundaries.
- **Communication:** artifact handoff through the plan/workspace/attestation rather than open chat.
- **Objective:** satisfy deterministic graders on software engineering, data engineering and incident response tasks.
- **Must-beat baselines:** unrestricted solo; restricted solo; no-plan; no-verifier; full team; compute-matched Solo-CoT/Solo-2Pass; deterministic grader without LLM attestation.
- **Metrics:** pass rate, partial score, cost, turns, false accept/reject, role violations, Teamwork Necessity Index (TNI), marginal Planner/Verifier contribution.
- **Ablations:** five public conditions; prompt-only versus OS-enforced roles; provider mixing; topology; hidden-seed generator; task difficulty/category.
- **Compute/runtime:** a keyless mock smoke test is public. A 90-task × five-condition leaderboard sweep is a moderate hosted-model job; the team uses two to three times the LLM calls of the unrestricted baseline. Docker is mandatory for the intended enforcement claim.
- **Public code/data:** [TeamBench repository](https://github.com/ybkim95/TeamBench), MIT; [931-row dataset](https://huggingface.co/datasets/ybkim95/teambench); [project page](https://teambench.github.io/); [preprint](https://arxiv.org/abs/2605.07073).
- **New benchmark need:** **no** for one-pass role separation. **Yes** for iterative oversight, strategic concealment, or decentralized peer verification.
- **Feasibility warning:** this is an arXiv preprint, not a verified NeurIPS 2026 acceptance; the dataset history explicitly removed a NeurIPS badge/citation. Its “oracle” is only an unrestricted single agent, **not a theoretical upper bound**—the project FAQ says so, and TNI may exceed 1. Treating `S_oracle` as optimal is deceptive. The site also reports a 49.4% verifier false-accept rate on grader-failing runs, so LLM attestation cannot replace the deterministic grader.

## Deceptive or infeasible setup flags

| Flag | Why it invalidates a result | Required control |
|---|---|---|
| Calling an unrestricted solo agent an “oracle” | Full access is not optimality; teams can exceed it | Say “unrestricted solo baseline”; reserve oracle for solved/ground-truth ceilings |
| LLM-versus-MARL score with unequal communication cost | Alem LLM messages are free alongside actions; MARL signals cost an action | Match channel, bits, timing and opportunity cost |
| Centralized state leak in a decentralized baseline | Converts the problem into a centralized POMDP | Log each agent's exact observation and reject illegal history access |
| Model samples presented as independent agents | Shared weights/prompts and correlated randomness shrink effective sample size | Analyze at run/seed level; report model and prompt clustering |
| Variable stopping “when stable” | Treatment affects its own horizon and exposure | Fixed preregistered horizon plus survival analysis |
| LLM judge as both treatment and ground truth | Circularly rewards its own style/preferences | Deterministic/environment labels or independent blinded human audit |
| “No communication” also removes memory/rules/actions | Ablation changes more than the channel | Mechanism-isolated toggles and token/turn matching |
| Shared file system called governed memory | Files alone lack scope, provenance, supersession and cross-episode persistence | Explicit lifecycle and policy tests |
| One seed or one conversation trajectory | LLM stochasticity and partner effects dominate | At least five seeds for cheap simulations; confidence intervals by run |
| Full Cicero retraining proposed as ordinary baseline | Official recipe asks for 256 GPUs; human training data unavailable | Use released checkpoint or drop the family |
| Full hosted-LLM Alem protocol | Up to 600,000 responses per condition | 100–200-step gated pilot, then justified scale-up |
| Full 100-agent SILO sweep without call ledger | Cost grows with agents × rounds × cases | Precompute upper bound and enforce a hard call/token cap |
| Melting Pot normalized score called optimality | Normalization uses random/exploiter anchors, not an exact optimum | Report raw/normalized score with anchor definitions |
| Preprint artifact described as accepted | Inflates evidence status | Verify venue proceedings; label TeamBench preprint as such |
| Cross-version Alem comparison | v0.2.0 changed world generation | Pin version/commit and do not pool incompatible runs |

## Minimum credible experiment portfolio

Do not attempt all families at full scale. A compact, falsifiable run can cover the seven requested themes with the following ledger.

| ID | Theme | Locked pilot | Cell/episode count | Cost gate |
|---|---|---|---:|---|
| E1 | decentralized planning | 6 MADP instances × 3 horizons × 4 controllers | 72 exact-evaluation cells | CPU; stop if no exact reference can be verified |
| E2 | ad hoc teamwork | 5 OvercookedV2 layouts × 6 public partners × 4 focal policies × 5 seeds | 600 episodes | fixed checkpoints; no training |
| E3 | strategic communication | 4 OpenSpiel games × 4 channel conditions × 5 seeds | 80 runs | CPU/tabular plus bounded LLM adapter |
| E4 | norms/reputation | 3 GovSim/RepuNet scenarios × 4 mechanism conditions × 5 seeds | 60 runs | record calls/tokens after first 12-run block |
| E5 | shared memory | 4 Caura failure modes × 4 policy bundles × 20 deterministic trials | 320 trials | no LLM required for primary systems claim |
| E6 | LLM teams | Alem 3 difficulties × {full, no-comms, no-scratchpad} × 3 episodes × 100 steps | 8,100 agent turns | hard stop before 10k-step protocol |
| E7 | oversight | 184 Who&When traces × 3 attribution methods | 552 trace-method evaluations | reuse cached scores where possible |

**Count:** 1,684 cells/episodes/trials plus 8,100 explicitly bounded Alem agent turns. These units are heterogeneous and must never be averaged into one score. TeamBench and SILO-BENCH are reserve transfers: add one only after E1–E7 pass reproducibility and cost gates.

## Recommended common reporting contract

Every run should emit one machine-readable record with:

```text
artifact_commit, environment_version, task_id, seed,
agent_count, agent_model_or_policy, role, observation_contract,
action_contract, communication_contract, memory_contract,
horizon, termination_reason, reward_or_success, baseline_id,
model_calls, input_tokens, output_tokens, wall_seconds,
parse_failures, retries, policy_or_trace_hash
```

Use three separate outcome panels:

1. **Task value:** return, success, optimality/regret where a true optimum exists.
2. **Coordination mechanism:** messages/bytes, topology, information acquisition/integration, partner robustness.
3. **Governance/oversight:** leakage, stale state, false blame, coverage, false accept/reject, repair cost.

No global “multi-agent intelligence” composite is justified by these environments.

## Bottom line

Use existing environments and spend novelty on the causal question, not on another wrapper. The safest near-term combination is exact MADP policy evaluation + OvercookedV2 partner shift + offline Who&When oversight, with GovSim/RepuNet or Caura as one focused governance extension. Alem is the best ecological LLM-team transfer if capped aggressively. Cicero and full Melting Pot training should remain references unless substantial dedicated compute is available.
